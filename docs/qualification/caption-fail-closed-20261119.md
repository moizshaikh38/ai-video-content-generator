# Requested-caption fail-closed output contract

2026-11-19, IST. Backup-branch correction only. No production deployment.

## Confirmed defect

The clip renderer caught most ASS generation errors and continued rendering without requested subtitles. It also silently skipped burn-in when cues existed but the ASS file was absent. The caption service could replace an unreadable saved editor project with transcript fallback or return an empty result when no transcript was available. These outcomes could incorrectly look like a successful captioned export.

## Correction

- Requested subtitle generation errors propagate to the existing fenced render-failure path. There is no subtitle-free success fallback.
- Nonempty cues require nonempty generated ASS dialogue and an on-disk file with exactly those generated bytes before the encoder starts. Missing, empty, unreadable or changed artifacts stop export.
- Captions use the render-bound saved editor-project snapshot, including explicit known absence. They cannot independently re-read a different saved revision. A bound project must match the clip and owner.
- Unreadable editor/transcript sources fail closed. A missing transcript is allowed only when an authoritative saved caption edit covers the requested interval. Explicitly deleted/empty covered cues stay empty and are not regenerated. An uncovered extension without a transcript is rejected.
- Caption extension errors are no longer logged-and-skipped. Existing source-quality/source-binding review gates remain in place.
- Caption-source read outages use the existing bounded retry budget. Artifact defects are not silently downgraded. Captions explicitly disabled at the clip level still bypass this renderer caption block.

## Evidence

- Final focused regression group: 68 tests passed. It includes render fencing, editor revision, retry budgets, streaming upload, render parity/recovery, caption artifact and caption-source cases. Frontend and server typechecks passed.
- Five actual caption-service/Mongo/ASS scenarios passed against the new loopback database `vireo_caption_contract_20261119_0049`. One synthetic editor project remains retained, with no transcript records. The checks cover missing source rejection, retained intentional empty edits, immutable snapshot use despite a newer stored project, exact ASS from a stored nonempty edit, and uncovered extension rejection. The two successful ASS files are 586 and 653 bytes.
- The new source-error unit suite uses synthetic repository responses and opens no database connection. It covers source-read errors, wrong owner/clip, explicit absence, empty coverage and actual ASS writing.
- An existing caption regression also generated two synthetic 540x960 still PNGs and compared caption/non-caption regions. That FFmpeg check took about 219 ms. The two PNGs plus ASS total 9,273 bytes. Pixels were inspected: the captioned frame has readable white words low in the frame; the control is blank. This is only a synthetic subtitle-presence check, not a real clip, new product visual, temporal proof or caption-accuracy proof.

## Limits

This prevents known false-success paths. It does not establish transcript correctness, word/audio synchronization, timing accuracy, actual video appearance, full-editor behavior, production auth/storage availability, ordinary automatic export, genuine 4K or restart/load safety. No new source acquisition, ASR, video encode, external storage write, provider spend or production data mutation was performed for this correction. Existing explicitly empty/silent content still needs an honest caption choice; missing caption data is no longer treated as proof of silence.

Shutdown inspection remains unresolved: HTTP close currently precedes awaiting background renders and other work before Mongo closes. No partial shutdown implementation or drain guarantee is included here.
