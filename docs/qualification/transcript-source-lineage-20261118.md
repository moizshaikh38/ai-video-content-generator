# Transcript source lineage, 18 Nov 2026

Development only. New processProjectVideo output records the verified source download receipt, prepared audio SHA256, exact buffer hashes at the existing provider abstraction boundary (including chunk/fallback requests), and a hash of persisted speech/review/provenance content. Internal provider failover transport attempts are not separately recorded. The hashes are integrity evidence, not word/timing accuracy or independent reference evidence.

Existing transcript reuse now requires a current strong source validator plus the content binding in the processing, project-controller cross-workflow, and Subtitle Studio reuse paths. Same-owner cross-project cloning retains review state, provenance and binding. Old or edited records stop for review rather than silently starting a paid transcription. A missing transcript after a zero-credit reuse reservation cannot fall through to a fresh provider call. New processing without a verified source download receipt stops before provider use. A source pointer/version change detected after provider work prevents promotion, but cannot undo the already-submitted provider work. No added provider call is made to recover that condition.

Qualification: actual local conditional HTTP source download, actual FFmpeg audio extraction, Mongo persistence and actual processing/reuse functions. Speech provider and plan entitlement are explicit synthetic stubs, no real STT call or accuracy claim. Exact downloaded source hash and submitted audio hash match the recorded receipts. Matching source reuses without another provider call. Same-size replacement validator, changed transcript, missing legacy receipt, source moving during provider work, wrong owner and vanished zero-credit reuse are rejected. Cross-project Subtitle Studio lineage copy is exercised. Concurrent late/failed request observer coverage uses a unit fixture, not a full long-source chunk/provider run.

15 source/quality/freshness tests passed. Separate actual replica-set credit suite: 12 passed. Its former URL-only success cases now assert a legacy-lineage stop and unchanged wallet; an existing zero-amount reservation is immediately settled by the ledger, not newly charged or necessarily marked released. Server TypeScript passed.

Not qualified: interactive browser review/retranscription recovery, legacy migration or automatic backfill, full long/chunked provider E2E, all alternate transcription producers, ordinary selection/export transcript source-lineage enforcement, race-free distributed transaction, provider recognition accuracy. Legacy projects will require a deliberate recovery/review design before this is a main/live candidate. No production data, auth, spend, 4K, main or deploy action.
