# Real-media evaluation admission, not a quality result

`npm run eval` currently audits corpus admission only. Exit2 means blocked. It does not analyze footage, call a provider, compute quality metrics, or certify publish-ready output. Every metric remains `not-measured` with null value until an actual qualified measurement exists. `npm run test:eval` checks gate behavior using synthetic contract examples, not media-quality results.

The empty committed manifest is intentional. No exposed clip has been relabeled as blind holdout, no rights claim is inferred from public availability, and no synthetic export counts toward20real clips. Retained diagnostic media is not redistributed. Local paths can be supplied in an owner-approved manifest, bytes are verified on audit. SourceGroup identifies common originals across windows/derivatives and cannot cross dev/holdout. Twenty different encodes of one source are not variety. Exposed development data cannot be holdout. Independent custodian must freeze genuinely unseen holdout before tuning. Approximately70/30 split uses20-40percent admission tolerance, not an output-quality threshold.

Each manifest entry requires id, kind real-source, sha256, sourceGroup, split, origin.url, rights basis/evidence/verified, positive durationSeconds, genre/language, explicit exposure, reference digests and local path. Holdout also records sealedAt/custodian/usedForTuning false. These declarations require source evidence and independent review; JSON fields cannot authenticate rights, exposure, references or human judgment by themselves. The script cannot detect dishonest declarations. Current reference hashes are admission placeholders until actual reviewed label files and provenance are supplied and checked; the harness does not claim to validate their semantic truth.

Coverage tags currently requested by this audit: podcast, talking_head, gaming_facecam, gaming_no_facecam, screen_share, sports, comedy, lecture_news; Hindi or Hinglish evidence. They describe corpus coverage, not production per-genre branches. Gaming target/action labels must follow the owner's player/action priority, not every HUD label. Evaluation-only target annotation never becomes a hardcoded production focus or automatic identity claim.

Before quality metrics are enabled, record human selections/complete-thought boundaries and uncertainty; source-time target/action and speaking-face boxes; reference captions and language; reviewed candidate plan/output hashes; exact code/config/decoder/inference versions; runtime/hardware; and measurement coverage. Decode/reference errors and unknown labels are not zero-error results. Candidate comparisons must use identical source windows and output dimensions. Do not aggregate known failures away. Whole-set and per-genre regressions block acceptance after baseline is real.

Existing server benchmark selectionMetrics math may be reused, but its synthetic golden/degraded and deterministic engine benchmark is not this real corpus. PLAN_CONSUMERS.md inventories current separate routes without asserting universal persisted plan parity.
