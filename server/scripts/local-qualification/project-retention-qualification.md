# Staged Free project retention, not live enforcement

New upload and URL project creation stamps a versioned policy derived from server-resolved creation entitlement. Free proposal is creation + 72 hours. Paid/developer has no Free deadline. Legacy records stay unchanged. Every policy explicitly has `enforcement: disabled`; no cleanup, access restriction, billing mutation or downgrade catch-up is implemented. Dashboard notices say removal is not enabled and expired proposals remain available. Upgrade-active retention/downgrade/reactivation grace must be settled before separate live enablement. No existing data deletion is authorized.

A pre-existing GET listProjects side effect deleted failed records. Listing is now read-only and retains failure/review states, with exact pagination total. This is separate from storage retention and does not hide rows as a substitute for retaining them.

Qualification: four focused tests; both TypeScript checks; actual local HTTP project routes/Mongo with isolated authentication and external-network rejection. Free creation ignores forged client policy/plan; paid no deadline; repeated list byte-identical including failed and review records; legacy has no retroactive policy; owner isolation and pagination limit2/total5; get reload preserves metadata.
